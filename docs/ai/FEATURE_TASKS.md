# Feature: Tasks

> Create tasks within a project, assign to a member, update status, list by project or assignee.

---

## Feature Scope

| Capability | Implemented? |
|---|---|
| Create task (title, description, status, priority, assignee, due date) | ✅ |
| List tasks by project | ✅ |
| List tasks by assignee ("My Tasks") | ✅ |
| Update task (status, priority, assignee, etc.) | ✅ |
| Upload task attachment (document) | ✅ Supabase only (Firebase: not implemented) |
| Task detail view | ✅ |
| Delete task | ❌ Not implemented (TODO) |
| Reorder tasks (position) | ❌ Not implemented (TODO) |
| Filter by status/priority | ❌ UI not implemented (data supports it) |

## Data Shape

### `tasks` (table / collection)

| Field | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key, auto-generated |
| `project_id` | UUID | FK to projects.id |
| `title` | string | Required |
| `description` | string \| null | Optional |
| `status` | enum: `todo`, `in_progress`, `in_review`, `done`, `cancelled` | Default: `todo` |
| `priority` | enum: `none`, `low`, `medium`, `high`, `urgent` | Default: `none` |
| `assignee_id` | UUID \| null | FK to profiles.id — the assigned member |
| `created_by` | UUID | FK to profiles.id — who created the task |
| `due_date` | date \| null | Optional deadline |
| `position` | integer | Default: `0` — for ordering |
| `created_at` | timestamp | Auto-set |
| `updated_at` | timestamp | Auto-set |

## Comparison: Firebase vs Supabase

### Create Task

| Aspect | Firebase | Supabase |
|---|---|---|
| **Method** | `addDoc(tasksRef, { ...taskData, status, priority, position, created_at, updated_at })` | `supabase.from('tasks').insert([{ ...taskData }]).select().single()` |
| **ID generation** | Auto-generated by Firestore (`docRef.id`) | Auto-generated UUID by Postgres |
| **Timestamps** | Manual `serverTimestamp()` for both fields | DB defaults `now()` for both fields |
| **Assignee validation** | ❌ None — app can assign anyone | ✅ DB trigger `validate_task_assignee` — checks assignee is a project member |
| **Attachment upload** | ❌ Not implemented | ✅ Calls `uploadTaskAttachment()` after insert |

### List Tasks by Project

| Aspect | Firebase | Supabase |
|---|---|---|
| **Method** | `query(tasksRef, where('project_id', '==', projectId))` | `supabase.from('tasks').select('*').eq('project_id', projectId).order('position')` |
| **Ordering** | ❌ Not ordered (needs composite index for multi-field ordering) | ✅ Ordered by `position` ascending |
| **Returns** | `snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }))` | `data` array directly |

### List Tasks by Assignee

| Aspect | Firebase | Supabase |
|---|---|---|
| **Method** | `query(tasksRef, where('assignee_id', '==', assigneeId))` | `supabase.from('tasks').select('*').eq('assignee_id', assigneeId).order('position')` |
| **Ordering** | ❌ Not ordered | ✅ Ordered by `position` |

### Update Task

| Aspect | Firebase | Supabase |
|---|---|---|
| **Method** | `updateDoc(taskRef, { ...updates, updated_at: serverTimestamp() })` | `supabase.from('tasks').update(updates).eq('id', taskId)` |
| **Auto updated_at** | Manual `serverTimestamp()` | Automatic via `handle_updated_at` trigger |
| **Assignee validation** | ❌ None | ✅ Trigger validates assignee is project member |

## Task Attachment Upload (Supabase Only)

The Supabase task service includes document upload for tasks:

```
1. Create task → get task ID
2. Fetch file as blob
3. Upload to 'task-attachments' bucket at path: task-{taskId}/{fileName}
4. Get public URL
5. (PENDING) Update task row with attachment URL — currently commented out due to missing column
```

| Aspect | Detail |
|---|---|
| **Storage bucket** | `task-attachments` |
| **Path pattern** | `task-{taskId}/{fileName}` |
| **Status** | ⚠️ Partially implemented — upload works but task table has no `attachment` column yet |

**Firebase equivalent**: Not implemented. Would use Firebase Storage with same path pattern.

---

## Supabase Automation

| Trigger/Function | Purpose |
|---|---|
| `validate_task_assignee` | Before INSERT/UPDATE on `tasks` — ensures `assignee_id` is a member of the task's project |
| `handle_updated_at` | Auto-sets `updated_at = now()` on any update |

### Firebase Equivalent
- No assignee validation — app trusts the client
- `updated_at` set manually with `serverTimestamp()`

## TypeScript Interface

Both services define the same interface:

```typescript
interface TaskData {
  project_id: string;
  title: string;
  description?: string;
  status?: string;    // 'todo' | 'in_progress' | 'in_review' | 'done' | 'cancelled'
  priority?: string;  // 'none' | 'low' | 'medium' | 'high' | 'urgent'
  assignee_id?: string;
  created_by: string;
  due_date?: string;
  position?: number;
  attachment?: any;   // Supabase only (file object from document picker)
}
```

## Known Gaps

1. **Firebase task attachment**: Not implemented — needs Firebase Storage upload similar to avatar upload
2. **Supabase attachment column**: The `tasks` table doesn't have an `attachment` column — the update after upload is commented out
3. **Firebase ordering**: `getTasksByProject` doesn't order results — should add `orderBy('position')` (requires composite index)
4. **Task delete**: Not implemented on either platform
5. **Task reorder**: Position field exists but no reorder logic implemented
